# 案例研究工作区

更新：2026-09-09。

## 改动边界

保持外层左侧 Agent、中间工作区、右侧案例集。只替换案例研究 tab 的内容，不修改研究框架、跨案例研究或案例集图谱的实现。

中栏首次进入且未选择案例时显示流程引导。创建案例后直接打开；选中案例后上半区是独立滚动的连续总结稿，摘要位于全文顶部，下半区默认是单案例完整图。选择片段切换子图，取消选择恢复完整图。引用打开中栏内部右侧原材料阅读区。

## 数据与后台

- 继续使用现有 `case_research_work(case_id,user_id)` 私有研究记录，未扩大旧材料的可见范围。
- 原件存放在 `case-workspace/{schemaId}-{caseId}-material/{materialUUID}/original/{filename}`；元信息与解析文本分别保存在同目录的 `metadata.json`、`parsed.json`。
- `/api/research-workspace` 提供材料上传、原件下载、解析内容、工作区快照和后台任务操作。所有请求校验案例访问权，写入要求 owner/editor，材料额外按用户研究记录隔离。
- `case_research_jobs` 保存队列、进度、错误与检查点。同一用户和案例最多一个活动任务。服务启动恢复未完成任务，失败可手动重试。
- 新材料按有稳定定位的原文块分批处理；复用之前的总结段落，更新片段必须保留旧引用。请求变化会重读材料；处理中到达的新材料或研究要求会触发后续任务。
- 每个总结片段携带段落引用及关系单元。当前版本的完整图合并同名同类型节点和同一时段的关系，同时保留多份证据。候选图不会自动写入其他 tab 的已发布知识图。

## 格式与边界

- PDF：按页解析，可显示原页并高亮来源文字区域。扫描件无文字时明确提示需要 OCR。
- DOCX：后端提取段落，前端使用经过标签/属性白名单处理的 Word 内容视图；保留基本格式与表格，不承诺原 Word 分页。
- DOC：服务器安装 `antiword` 后可解析为段落内容视图。
- TXT/Markdown/CSV：保存文本快照和段落位置，Markdown 以排版正文展示。
- 其他格式先归档，明确显示未接入文字识别或转写。单份上限 20 MB。
- 引用校验验证原文摘录与位置，不能替代研究者对事实和证据支持关系的判断。
- Agent 对话按用户和案例隔离，保存在当前浏览器 sessionStorage；材料、稿件和任务保存在服务端。

## 验证与部署

`node --test server/tests/research-model.test.js` 覆盖定位、拒绝虚构/歧义引用、稳定 ID、旧证据保留和长材料完整切分。

`server/scripts/research-workspace-smoke.mjs` 是只监听回环地址的临时验收服务器，使用合成案例与本地模拟模型，验证原件、重复检测、多批材料、访问控制、失败保护与重试。默认清理测试数据；`KEEP_REVIEW=1` 保留至进程收到 SIGTERM/SIGINT 并清理。不要将它作为正式服务运行。

正式部署前备份代码与 dist；在项目根执行 `npm run build`，后端有改动才重启 `caseflow-server`。恢复旧代码不会删除新增研究记录或原始材料。
